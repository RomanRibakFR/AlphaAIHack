# Моки внешних сервисов — тестовые данные

Данные для мок-сервиса: 17 вымышленных компаний, по одной на каждую ветку пути заявки. Сам сервис пишет бэкенд; здесь — то, что он отдаёт.

Полное описание полей — `docs/mocks-format.md`.

## Что в архиве

Архив повторяет структуру репозитория: распаковывать в корень проекта.

| Путь | Что это | Нужно для |
|---|---|---|
| `mocks/companies/*.json` | 17 компаний, файл = `<ID>_<ИНН>.json` | **мок-сервис** |
| `docs/mocks-format.md` | описание формата, поведение мока, таблица компаний | **мок-сервис** |
| `mocks/check_mocks.py` | проверка данных: формат, контрольные цифры, ветки | проверка после любых правок |
| `mocks/generate_mocks.py` | генератор, из которого получены JSON | если нужно поменять или добавить компанию |
| `config/decision_policy.yaml` | параметры кредитной политики | нужен `check_mocks.py`; бэкенду — для модуля решения |
| `docs/application-states.md` | статусы и переходы (T01…T22) | расшифровка `meta.expected.path` |
| `docs/decision-policy.md` | правила решения (SF01…, M1…) | расшифровка `meta.expected.reason` |

## Что нужно от мок-сервиса

1. **Загрузка.** При старте прочитать все `mocks/companies/*.json`, построить индекс по `egrul.inn`.
2. **Маршруты** — каждый отдаёт свой раздел файла:
   - `GET /egrul/{inn}` → `egrul`
   - `GET /fns/{inn}` → `fns`
   - `GET /zsk/{inn}` → `zsk`
   - `GET /bki/{inn}` → `bki`
   - `GET /bank/{inn}` → `bank`
3. **Не отдавать** раздел `meta` и служебное поле `_mock`.
4. **Поведение `_mock`.** Поле может быть в любом разделе, сейчас есть только у C17 в `bki`:
   - `unavailable` — ответить 503;
   - `timeout` — не отвечать дольше таймаута бэкенда;
   - `not_found` — ответить 404;
   - `delay_ms` — задержка перед ответом.
5. **Неизвестный ИНН** — 404.
6. **Задержки по умолчанию** (предложение): ЕГРЮЛ ~300 мс, БКИ ~1500 мс — чтобы в кабинете было видно, как идут подшаги «проверяем данные → смотрим кредитную историю».

## Важное для логики бэкенда

- **Обороты — только `credit_net`** (очищенные). `credit_total` включает переводы самому себе и полученные кредиты — это не выручка.
- **Кредиты нашего банка есть в двух местах:** в `bki.accounts` (`creditor_kind = OWN_BANK`) и в `bank.own_loans` с тем же `contract_uid`. Долговую нагрузку считать только по БКИ, иначе платёж посчитается дважды.
- **Сводки в БКИ нет** — общий долг и просрочку считать из `accounts`.
- **У ИП в БКИ есть личные кредиты** (автокредит, кредитная карта): история ИП и физлица одна, они входят в долговую нагрузку.
- **Деньги — целые рубли, доли — дроби** (`0.17` = 17%), даты — `ГГГГ-ММ-ДД`.
- **Дата выгрузки данных зафиксирована — 24.10.2026.** Срок ведения бизнеса считать от неё (или от текущей даты — тогда со временем ожидаемые исходы могут сдвинуться).

## Проверка данных

Python 3.10+ и PyYAML:

```bash
pip install pyyaml
python mocks/check_mocks.py
```

Должно быть 17 строк с ✓ и `ошибок: 0`. Скрипт — инструмент проверки данных, а не код продукта: правила решения в нём упрощённо повторяют `docs/decision-policy.md`, чтобы убедиться, что каждая компания попадает в свою ветку.

## Как менять данные

- **Основной способ:** поправить компанию в списке `COMPANIES` в `generate_mocks.py` → `python mocks/generate_mocks.py` → `python mocks/check_mocks.py`.
- **Ручная правка JSON** допустима, но после неё генератор не запускать — он перезапишет файлы.
- **По вопросам данных** — к Аскару (задача 4).
