# Фронтенд: что сделано

Состояние на 24 октября 2026 года.

## Посмотреть без запуска

[`snapshot/landing.html`](snapshot/landing.html) — вся продуктовая страница в одном файле.
Открывается двойным кликом, работает без сервера и без докера: калькулятор считает,
вкладки переключаются, вопросы раскрываются, анимации играют.

Чего в снимке нет: запросов к API. Каталог продуктов показывается из запасной копии
(о чём внизу страницы есть честная строчка), а вход по ИНН не сработает — для него
нужен живой бэкенд. Снимок пересобирается командой `npm --prefix frontend run snapshot`
и содержит только наш код: ни чужих шрифтов, ни чужих картинок внутри нет.

Статичные снимки экранов — в [`screens/`](screens).

## Посмотреть живьём

```bash
docker compose up --build
```

Сайт на http://localhost:3000. Либо без докера, если бэкенд уже поднят:
`npm --prefix frontend run dev` — http://localhost:5173.

напрямую, закрытие возвращает на главную.

## Из чего собрано

```
frontend/src/
  landing/        продуктовая страница: секции, окно входа, тексты
  screens/        экраны кабинета (пока голый скелет)
  components/     части карточки заявки: форма, действия, история
  api/            типы ответов бэкенда и клиент с разбором ошибок
  lib/            форматирование, сессия, движок анимаций
  ui/             дизайн-система: токены, примитивы, анимации
```

Дизайн-система — не копия CSS, а пакет `@alfalab/core-components` как зависимость
(MIT). Фирменный шрифт не используем: у Alfa Sans нет открытой лицензии, а кейс
запрещает закрытые. Подробности в [`../design-system/README.md`](../design-system/README.md).

## Анимации

Словарь эффектов взят с 60fps.design (reveal, stagger, ticker, grow, spring, draw,
shimmer). Их собственные сниппеты на SwiftUI, поэтому для веба всё написано заново:
`lib/motion.ts` и `ui/motion.css`.

Что где: въезд геро при загрузке, карточка заявки сама проходит путь по кругу,
цифры показателей добегают до значения, секции проявляются при прокрутке с задержкой
друг за другом, платёж в калькуляторе догоняет слайдер, линия между этапами
прочерчивается, карточки приподнимаются под курсором, окно входа всплывает
с размытием фона, под шапкой полоска прочитанного.

При системной настройке «уменьшить движение» всё это выключается — не ускоряется,
а именно выключается, и страница сразу в конечном виде.

Появление считается своим слушателем прокрутки, а не `IntersectionObserver`.
Причина в комментарии к `useInView`: наблюдатель молчит, если секцию проскочили
рывком, и блок навсегда остаётся невидимым.

## Что фронт берёт у бэкенда

Каталог продуктов, поиск компании по ИНН, черновик заявки с автосохранением,
отправка и отзыв. Деньги приходят строками (`"2000000.00"`), в типах они `string`.
Кнопки рисуются по `available_actions` из ответа, статус показывается
по `status.title` и `status.hint` — логика переходов на фронте не дублируется.

## Чего не хватает

**Блокирует основной сценарий.** По ответам организаторов демо должно доходить
до выдачи кредита, а не до экрана с одобрением. Для этого нужны ручки
`accept`, `decline`, `sign`: сейчас бэкенд отдаёт эти действия в `available_actions`,
но POST-эндпоинтов нет. Кнопки нарисованы и заблокированы.

**Заявка зависает.** Переход `submitted → validation` делает «система», запускать
её некому — скоринга нет. Карточка заявки опрашивает статус и честно пишет об этом.

**Нет полей решения.** Для статусов `approved`, `counter_offer`, `rejected`
и `needs_info` показывать нечего: в `ApplicationOut` нет ни одобренной суммы,
ни ставки, ни причины отказа, ни срока действия предложения. Организаторы требуют
прозрачности логики решения, так что это нужно и для оценки.

**Экран сотрудника пустой.** Нужны выборка заявок на ручной разбор, карточка
с результатами проверок и баллами, ручка решения.

**Кабинет не оформлен.** За входом — скелет на голых браузерных стилях.
Продуктовая страница готова, кабинет ещё нет.

Все эти места помечены прямо в интерфейсе красной пунктирной рамкой с объяснением,
чего не хватает, — чтобы на защите никто не принял заглушку за готовое.

## Открытые вопросы

- **Ставки.** 15,5–18,5% при ключевой ставке 14% выглядят неправдоподобно узко
  для МСП, а организаторы требуют правдоподобия. Цифры в `backend/app/seed.py`
  помечены автором как выдуманные, их стоит пересчитать.
- **Новостная лента.** В требованиях к сдаче есть строчка про ленту под клиента,
  но в 52 вопросах с вебинара её не спросил никто. Сейчас на её месте заглушка.
- **Как фронт узнаёт о смене статуса** — поллинг, SSE или websocket. Сейчас поллинг
  раз в три секунды.
