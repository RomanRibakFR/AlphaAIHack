# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (кейс Альфа-Банка, Альфа-Хак 2026):
личный кабинет клиента, внутренняя обработка заявки, скоринг и кредитное решение в едином процессе.

README пока черновой — архитектуру и схемы допишем по ходу.

## Состав

| Сервис | Технологии | Порт | Назначение |
| --- | --- | --- | --- |
| `frontend` | React 18 + TypeScript + Vite, nginx | 3000 | Личный кабинет клиента |
| `backend` | Python 3.12, FastAPI, SQLAlchemy, Alembic | 8000 | Кредитный конвейер, API |
| `mocks` | Python 3.12, FastAPI | 8001 | Заглушки ЕГРЮЛ/ЕГРИП, ФНС, БКИ |
| `db` | PostgreSQL 16 | — | Хранилище заявок |

## Запуск

Требуется Docker Desktop (Docker Engine 24+ с Compose v2).

```bash
docker compose up --build
```

- Кабинет: http://localhost:3000
- Swagger UI: http://localhost:8000/api/docs
- Моки: http://localhost:8001/docs

## Как принимается решение

После отправки заявку ведёт конвейер (`backend/app/pipeline.py`):

1. **Проверка данных** — заполнено ли всё, подходят ли сумма и срок под продукт.
2. **Внешние проверки** — реестр, БКИ, ФНС и обороты по счёту (моки). Если выручка в анкете
   в 1,5 раза больше оборотов, просим выписку из других банков. Если источник не ответил — заявку смотрит специалист.
3. **Скоринг и решение** (`backend/app/scoring.py`):
   - стоп-факторы: ликвидация, текущая просрочка, долг по налогам, бизнес моложе требования продукта;
   - скоркарта из 5 факторов (срок работы, кредитная история, долговая нагрузка, стабильность оборотов,
     сумма к выручке) → балл → вероятность дефолта `PD = 1 / (1 + exp(α + β·Score))`;
   - по PD: одобрение, контрпредложение, ручная проверка или отказ; ставка растёт вместе с риском;
   - сумму урезаем, если с новым кредитом платежи превысят 50% оборота.

Коэффициенты экспертные — вся настройка в `backend/app/scoring_config.py`. Это структура логистической регрессии:
на реальной истории банка коэффициенты обучаются, а конвейер остаётся прежним. Решение хранит вклад каждого фактора,
поэтому видно, почему оно принято.

Подписание условное: код подтверждения показывается прямо в кабинете вместо SMS. Выдача — смена статуса и график платежей.

## API

Полное описание — в Swagger: http://localhost:8000/api/docs

Клиент:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/products` | каталог продуктов |
| GET | `/api/companies/lookup?inn=` | данные компании из реестра |
| POST | `/api/applications` | создать черновик |
| GET | `/api/applications?inn=` | заявки компании |
| GET | `/api/applications/{id}` | заявка: статус, предложение или причина отказа, кнопки, история |
| PATCH | `/api/applications/{id}` | автосохранение черновика |
| POST | `/api/applications/{id}/documents` | загрузить документ (по дозапросу) |
| POST | `/api/applications/{id}/submit` | отправить в банк |
| POST | `/api/applications/{id}/withdraw` | отозвать |
| POST | `/api/applications/{id}/accept` | принять предложение |
| POST | `/api/applications/{id}/decline` | отказаться от предложения |
| POST | `/api/applications/{id}/sign` | подписать кодом → выдача |

Сотрудник банка:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/backoffice/applications` | очередь ручной проверки |
| GET | `/api/backoffice/applications/{id}` | анкета, ответы источников, баллы и решения |
| POST | `/api/backoffice/applications/{id}/decision` | одобрить, контрпредложение, отказ или дозапрос |
