# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (кейс Альфа-Банка, Альфа-Хак 2026):
личный кабинет клиента, внутренняя обработка заявки, скоринг и кредитное решение в едином процессе.

README пока черновой — архитектуру и схемы допишем по ходу.

## Запуск

Требуется Docker Desktop (Docker Engine 24+ с Compose v2).

```bash
docker compose up --build
```

- Кабинет: http://localhost:3000
- Swagger UI: http://localhost:8000/api/docs
- Моки: http://localhost:8001/docs

Настройки — в `.env` (пример: `.env.example`). Для демо истечения сроков можно сократить ожидание клиента
до минут: `TIMEOUT_OFFER_MINUTES=2` и т. п.

## Как принимается решение

Подробно — [docs/decision-policy.md](docs/decision-policy.md). Коротко, после отправки заявку ведёт конвейер
(`backend/app/pipeline.py`):

1. **Проверка полноты** — для инвестиционного кредита нужен залог. Отчётность юрлица банк берёт сам из ГИР БО.
2. **Проверки** — ЕГРЮЛ, ФНС, ЗСК, данные счёта, ГИР БО, потом кредитная история. Стоп-факторы SF01–SF06 — сразу отказ.
   Если выручка в анкете больше оборотов по счёту на 30%+ — просим выписку из другого банка.
   Источник не ответил после повторов — заявку смотрит специалист.
3. **Лимит и условия** (`backend/app/decision.py`) — новый платёж по потолку ставки ≤ 10% поступлений, вся нагрузка ≤ 17%,
   у овердрафта ≤ 50% оборота, у инвестиционного ≤ 60% залога; если сумма не помещается — сначала больше срок,
   потом меньше сумма.
4. **Оценка риска** (`backend/app/pd_model.py`) — модель задачи 2 (`models/pd/<ip|ul>/score.py`) на подобранных
   условиях: PD, вклад каждого признака. Вход собирается из данных источников (`backend/app/features.py`,
   эталон — `model_inputs` в `mocks/check_mocks.py`).
5. **Политика** — класс A/B/C/D (граница C/D — PD, при которой ставка упирается в потолок продукта),
   ставка = ключевая + маржа + PD × LGD (Базель III: 40% без залога, 20% на покрытую залогом часть);
   класс C, крупные, залоговые и с неснятым расхождением — к специалисту с готовой рекомендацией.

> **Модель обучена на синтетике.** Её PD — демонстрация процесса, а не банковская оценка.
> При переобучении достаточно заменить `models/pd/<ip|ul>/model.json` — контракт «вход → PD» не меняется.

Подписание условное: код подтверждения показывается прямо в кабинете вместо SMS. Выдача — смена статуса и график платежей.
Сроки ожидания клиента (14 / 30 / 5 дней) проверяет фоновый таймер.

## API

Полное описание — в Swagger: http://localhost:8000/api/docs

Клиент:

| Метод | Путь | Что делает | Переход |
| --- | --- | --- | --- |
| GET | `/api/products` | каталог продуктов | |
| GET | `/api/companies/lookup?inn=` | данные компании из реестра | |
| POST | `/api/applications` | создать черновик | |
| GET | `/api/applications?inn=` | заявки компании | |
| GET | `/api/applications/{id}` | заявка: статус, подшаги, запросы банка, предложение или отказ, кнопки, история | |
| PATCH | `/api/applications/{id}` | автосохранение черновика | |
| POST | `/api/applications/{id}/documents` | загрузить документ | |
| POST | `/api/applications/{id}/submit` | отправить в банк | T01 |
| POST | `/api/applications/{id}/provide-info` | дополнил то, что запросил банк | T05 |
| POST | `/api/applications/{id}/accept` | принять предложение (можно выбрать вариант) | T17 |
| POST | `/api/applications/{id}/sign` | подписать кодом → выдача | T19 |
| POST | `/api/applications/{id}/decline` | отказаться от предложения | T21 |
| POST | `/api/applications/{id}/cancel` | отозвать заявку | T21 |

Сотрудник банка:

| Метод | Путь | Что делает | Переход |
| --- | --- | --- | --- |
| GET | `/api/backoffice/applications` | очередь ручной проверки | |
| GET | `/api/backoffice/applications/{id}` | анкета, ответы источников, признаки, вклад в оценку, рекомендация | |
| POST | `/api/backoffice/applications/{id}/decision` | одобрить / отказать / запросить данные | T14 / T15 / T16 |

Чат с поддержкой. Переписка привязана к компании по ИНН, а не к заявке:
вопрос чаще всего возникает до подачи или не про конкретную заявку.

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/chat?inn=` | переписка компании с поддержкой |
| POST | `/api/chat?inn=` | клиент пишет в поддержку |
| GET | `/api/backoffice/chats` | диалоги со счётчиком неотвеченных |
| GET | `/api/backoffice/chats/{inn}` | переписка с компанией |
| POST | `/api/backoffice/chats/{inn}` | ответ поддержки |

Открытие переписки и ответ помечают сообщения другой стороны прочитанными.
