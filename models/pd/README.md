# Модели PD для ИП и юридических лиц

Версия: `external099_micro_v2`, 25.10.2026. Поставка из
`alfa_pd_training_bundle_099_2026-10-25.zip`; веса и код расчёта сохранены без изменений.

Две логистические регрессии: ИП — 11 признаков, ЮЛ — те же 11 плюс 8 показателей отчётности.
Результат — демонстрационная вероятность того, что непогашенная часть платежа по новому
кредиту достигнет 90 календарных дней просрочки в следующие 12 месяцев.

## Файлы

- `ip/model.json`, `ul/model.json`: коэффициенты, свободные члены, порядок признаков,
  преобразования, границы обрезки, стандартизация и контракт входа.
- `ip/score.py`, `ul/score.py`: расчёт на Python, только стандартная библиотека.
- `ip/scorer.js`, `ul/scorer.js`: альтернативный расчёт на JavaScript.
- `ip/coefficients.csv`, `ul/coefficients.csv`, `coefficients_all.csv`: открытые веса
  и параметры подготовки признаков для просмотра; для исполнения использовать JSON.
- `examples/ip.json`, `examples/ul.json`: вымышленные входы из тестовых компаний задачи 4 v2.

## Запуск из корня репозитория

```bash
python models/pd/ip/score.py models/pd/examples/ip.json
python models/pd/ul/score.py models/pd/examples/ul.json
```

Скрипт автоматически читает соседний `model.json`. При необходимости модель можно
передать явно: `--model models/pd/ip/model.json`.

Для вызова из приложения загрузите нужный `score.py` как модуль и вызовите
`result = module.score(inputs, model)`, где `model` — прочитанный `model.json`.
Успех: `status = SYNTHETIC_SIMULATOR`, вероятность в `pd_probability` (0..1),
вклады в `contribution_details`. Неверный или неполный вход: `REQUEST_DATA`,
`pd_probability = null`. Это запрос данных, а не PD = 0 и не автоматический отказ.

## Вход

Общие сырые поля для обеих моделей:

| Поле | Значение |
|---|---|
| `business_age_years` | возраст бизнеса в годах |
| `msp_category` | `micro` или `small` |
| `okved_main` | строка ОКВЭД2, например `47.11` |
| `monthly_receipts_rub` | средние очищенные поступления за 12 месяцев, рубли |
| `monthly_operating_outflows_rub` | средние операционные расходы, без кредитных платежей и переводов себе |
| `existing_monthly_debt_service_rub` | сумма действующих ежемесячных платежей, без дублей |
| `new_monthly_debt_service_rub` | положительный платёж по рассматриваемому новому кредиту |
| `receipts_growth_6m_pct` | (среднее последних 3 месяцев / среднее предшествующих 3 − 1) × 100 |
| `receipts_cv_pct` | стандартное отклонение 12 месяцев с ddof=0 / среднее × 100 |
| `cash_reserve_rub` | доступный денежный остаток на дату оценки, не средний остаток |
| `largest_customer_share_pct` | доля крупнейшего покупателя, проценты |

В полях `*_pct` число `15` означает 15%, не `0.15`.
У ЮЛ дополнительно: `unit` (`rub` / `thousand_rub`), `report_form` (`full` /
`simplified`), `assets`, `equity`, `current_assets`, `current_liabilities`,
`revenue`, `net_profit`, `ordinary_expenses`. Суммы отчётности должны иметь одну
выбранную единицу измерения. `ordinary_expenses = null` допускает подстановку
медианы обучающей выборки с флагом пропуска. Остальные обязательные данные
медианами автоматически не заменяются. Строка 2120 полного и упрощённого отчёта
имеет разный смысл; форма отчётности передаётся отдельным признаком.

## Данные, качество и ограничения

Обучение: 40 000 вымышленных заёмщиков, по 20 000 в каждом сегменте.
Для каждого сегмента: 14 000 обучение, 3 000 калибровка, 3 000 проверка.
События: ИП 2 195 / 463 / 461, ЮЛ 2 162 / 453 / 467 соответственно.
Всего 6 201 синтетическое событие из 40 000 (15,5025%). Денежные потоки,
долги, будущие шоки и просрочки сгенерированы; 960 000 месячных записей.
Открытые реестры и отчётность использованы как структурные профили и финансовые
доноры. Реальные исходы банкротства не использованы как метки этих моделей.
Исходные и обучающие таблицы остаются в полном архиве; для расчёта PD они не нужны.

Gini на отложенной синтетической выборке: ИП 85,39%, ЮЛ 85,77%.
Это качество воспроизведения симулятора, не подтверждённое качество кредитного
скоринга на реальных клиентах банка.

Изменены только свободные члены, чтобы средняя PD микро на калибровочной части
составила 9,9% отдельно у ИП и ЮЛ. Это сценарная настройка по внешнему ориентиру
НКР, не эмпирическая калибровка реальных кредитных дефолтов: определения события
в статистике рынка и нашем симуляторе различаются. Малые предприятия отдельно
не калиброваны. Коэффициенты факторов, порядок рисков и Gini не изменены.
Свободные члены: ИП `-4.484366139409423`, ЮЛ `-4.399106388544836`.

Модель симулировала 12 ежемесячных платежей. Применение к овердрафту и длинному
инвестиционному кредиту является приближением и требует продуктовых проверок.
Пороги одобрения, классы риска, LGD, ставки и лимиты — отдельная кредитная политика.

## Подключение к AlphaAIHack

Бэкенд вызывает `score.py` как есть: вход собирает `backend/app/features.py` (функция `model_inputs`,
то же правило, что в `mocks/check_mocks.py`), вызов — `backend/app/pd_model.py`, пути к `model.json` —
`config/decision_policy.yaml` → `model`. Классы риска, LGD, ставки и лимиты — кредитная политика
(`backend/app/decision.py`).
